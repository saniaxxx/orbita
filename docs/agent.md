# orbita-agent

Ядро голосового канала: занимает место processor на порту 8080, говорит с
quasar по тому же WebSocket-протоколу (`/process`), хранит диалоги и задачи в
SQLite и исполняет штатные директивы станции.

## Что умеет

- `/process` — `prepare` + `process`, один финальный `partialResponse`.
- **Директивы станции** (D-15). На `prepare` quasar присылает карту
  `directiveFunctions` (18 функций: громкость, таймеры, будильники, музыка,
  Bluetooth). Агент:
  - хранит карту на соединение;
  - отвечает на громкость и таймеры детерминированным быстрым путём, без LLM;
  - остальные функции вызывает через `function_calls` модели;
  - проверяет имя по пришедшей карте и `required`-поля схемы аргументов;
  - возвращает в `partialResponse.directives` пары `{name, arguments}`, которые
    quasar превращает в `TDirective`;
  - зеркалит нативные таймеры в SQLite (`kind = native_timer`), но **не**
    отправляет их push-ом: таймер исполняет станция.
- **MCP-поиск**. `AGENT_MCP_SERVER_URLS=search#http://127.0.0.1:8899/mcp`
  подключает `orbita-mcp-search`; инструмент виден модели как `search_search`.
  Если модель вызывает его, агент делает `tools/call`, кладёт результат в
  сообщение `role=tool` и повторяет запрос к LLM — два прохода, как у processor.
  `tools/list` кэшируется на старте; при 404 сессия MCP переинициализируется.
  Для погоды, новостей, курсов, цен и пробок поиск вызывается
  **детерминированно**, без выбора модели: локальная модель ненадёжно решает,
  когда звать инструмент. Поисковый ответ использует 4 последних сообщения
  истории.
- **Android TV**. Отдельный MCP-сервер `orbita-tv`:
  `AGENT_MCP_SERVER_URLS=...,tv#http://127.0.0.1:8898/mcp`. Модель видит
  `tv_state`, `tv_power`, `tv_key`, `tv_volume`, `tv_app`, `tv_input`,
  `tv_list`, `tv_search`. Питание только явное (`tv_power` с `on=true/false`),
  `tv_key` запрещает `POWER`; сертификат клиента `0600` и в git не попадает.
  «Найди на ютубе котиков» и «включи клип про кота» открывают результаты
  поиска YouTube; конкретное видео само не запускается.
  TV-команды разбираются детерминированно **до** домашнего пути. Если в фразе
  есть телевизор, вытяжка, приточка, увлажнитель, котёл, замок, ворота,
  розетка или шторы, домашний быстрый путь света не запускается — иначе
  «включи телевизор в детской» включает свет в детской. Подробности —
  `docs/tv.md`.
- **Речевой текст**. Обращение «Алиса, …» срезается перед обработкой; «Источник:
  …» вырезается из ответа; ответы с JSON или `function_calls:` (в том числе без
  скобок и в ```json) разбираются или вычищаются, чтобы модель не зачитывала
  JSON вслух.
- **Напоминания** без LLM: «через N минут», «через одну минуту», «через
  двадцать пять минут», «через полчаса», «в HH:MM», «завтра в HH:MM». Время
  считается в `Europe/Moscow`, хранится в UTC.
- **Диалог** с LLM: локальная `llama.cpp` (D-16), системный промпт, последние
  `HISTORY_LIMIT` сообщений; ответ разворачивается из JSON-обёртки
  (`text`/`reply`/`content`). О себе агент говорит в женском роде («я нашла»,
  «я включила») — это требование системного промпта. Внешний провайдер
  пробовали и отключили: 0,3–7,9 с
  на проход и ненадёжный выбор инструментов. Фолбэк-обёртка осталась в коде, но
  на стенде выключена (`AGENT_FALLBACK_BASE_URL=`).
- **Диагностика**: сервер пишет `process` (что пришло) и `process done`
  (`ms`, текст ответа, число действий), поэтому долгие и неверные ответы
  разбираются по журналу без догадок.
- **Планировщик**: due-задачи уходят в quasar `POST
  /devices/{duid}/push/text` (`{"eventText": "..."}`), retry 30 с, до 3 попыток.
- SQLite WAL, восстановление `running`-задач после рестарта, аудит.

## Архитектура каналов

Ядро не знает про станцию: оно возвращает `Outcome { text, actions }`, где
`Action` — типизированное действие (`SetVolume`, `SetTimer`, `Directive`), а
сессия — `SessionKey { channel, principal }`. Адаптер канала превращает действия
в свои примитивы: станция — в директивы, Telegram и веб со временем — в текст и
уведомления. Поэтому набор функций LLM — свойство канала, а не глобальный.

Код: `src/action.rs` (действия, сессии), `src/fastpath.rs` (громкость, таймеры,
напоминания), `src/channel/station.rs` (карта `prepare`, валидация, директивы),
`src/agent.rs` (маршрутизация и диалог), `src/server.rs` (WebSocket и ответ).

## Запуск локально

```sh
OPENAI_BASE_URL=http://127.0.0.1:8090/v1 \
OPENAI_MODEL=qwen3.5-9b-q4km \
AGENT_DB=/tmp/orbita-agent.db \
QUASAR_API_URL=http://127.0.0.1:31121 \
cargo run -p orbita-agent
```

Проверка без станции:

```sh
cargo run -p orbita-cli -- ask "привет"
cargo run -p orbita-cli -- ask "напомни через одну минуту проверить чай"
```

`ask` ходит в `ws://127.0.0.1:8080/process`.

## Установка и замена processor

На тестовом стенде processor уже удалён: агент занимает 8080, юнит
`deploy/systemd/orbita-agent.service` включён, `orbita-warmup` ждёт агента.

1. Собрать: `cargo build --release -p orbita-agent`.
2. Остановить старый processor (если он ещё есть):
   `systemctl stop orbita-processor && systemctl disable orbita-processor`.
3. Установить юнит, при необходимости поправить `OPENAI_BASE_URL`,
   `QUASAR_API_URL` и `DEFAULT_DUID`.
4. Запустить: `systemctl daemon-reload && systemctl enable --now orbita-agent`,
   проверить `curl -s http://127.0.0.1:8080/health`.
5. quasar не меняется: `PROCESSOR_BASIC_URL` уже указывает на 8080.
6. Проверить `orbita-cli ask "привет"`, голосом «Алиса, привет», «Алиса,
   громче», «Алиса, поставь таймер на две минуты».
7. Напоминание: «напомни через одну минуту проверить чай»; push придёт через
   минуту.

Откат: `systemctl stop orbita-agent && systemctl enable --now orbita-processor`
(юнит processor при необходимости восстанавливается из `deploy/systemd/`).

## Переменные

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `PORT` | `8080` | порт `/process` |
| `OPENAI_BASE_URL` | `http://127.0.0.1:8090/v1` | llama.cpp |
| `OPENAI_MODEL` | `qwen3.5-9b-q4km` | модель |
| `OPENAI_API_KEY` | пусто | ключ llama, если нужен |
| `AGENT_DB` | `/var/lib/orbita-agent/agent.db` | SQLite |
| `QUASAR_API_URL` | `http://127.0.0.1:31121` | management API quasar |
| `AGENT_MCP_SERVER_URLS` | пусто | MCP-серверы `имя#url` через запятую; поиск `search#http://127.0.0.1:8899/mcp`, TV `tv#http://127.0.0.1:8898/mcp` |
| `DEFAULT_DUID` | нет | станция, если quasar не передал `deviceId` |
| `HISTORY_LIMIT` | `12` | сообщений истории в промпт |
| `AGENT_FALLBACK_BASE_URL` | локальная llama | второй LLM на случай, если основной молчит дольше таймаута; пусто — выключено |
| `AGENT_FALLBACK_MODEL` | `qwen3.5-9b-q4km` | модель фолбэка |
| `AGENT_FALLBACK_API_KEY` | пусто | ключ фолбэка |
| `AGENT_PRIMARY_TIMEOUT_MS` | `2500` | сколько ждать основной LLM до фолбэка |
| `SCHEDULER_INTERVAL_MS` | `1000` | тик планировщика |

## Проверки

```sh
cargo test -p orbita-agent
cargo clippy -p orbita-agent --all-targets -- -D warnings

# реальный MCP-сервер (на хосте, откуда он доступен)
AGENT_MCP_URL=http://127.0.0.1:8899/mcp \
  cargo test -p orbita-agent --test mcp real_search_server_if_configured
```

36 unit-тестов, контракт `/process`, тесты директив (`tests/directives.rs`,
18 сценариев), MCP-клиент (`tests/mcp.rs`: 4 теста с фейковым сервером,
включая SSE с пустым priming-событием, плюс опциональный реальный) и голосовой
харнесс `deploy/verify/run-directives.sh` —
13 из 13 сценариев через симулятор станции. Голосом на реальной станции
проверены приветствие, громкость и таймер (L3).

04.11.2026 MCP-версия агента развёрнута в CT 101: real-тест 5/5, включая
`real_search_server_if_configured`; в журнале `MCP tools loaded tools=1`;
живой WS-запрос «какая сейчас погода в Москве» прошёл через SearXNG и вернул
погоду (стенд, без станции; не L4). Поиск голосом через станцию ещё не
проверялся. Бэкап прежнего бинарника и юнита — `/root/backup-agent/` в CT 101.

Задержки после правок (WS, до синтеза): приветствие 1,19 с, погода 1,9–2,05 с
(поиск 0,56–0,69 с + проход модели 1,2–1,5 с). На провайдере было 0,3–8,8 с.
