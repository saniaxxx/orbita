# orbita — спецификация

Источник истины о том, что orbita делает и каким должна быть. Разработка идёт от спеки: каждое
изменение поведения, протокола, развёртывания или достигнутый результат сначала (или в том же
коммите) отражается здесь. Требования пронумерованы (`FR-…`, `NFR-…`, `D-…`): на номера
ссылаются коммиты и тесты. Цифры замеров — в [measurements.md](measurements.md).

## 1. Назначение и границы

orbita — голосовой сервер для ESPHome-спутников (колонки с [pulsar](https://github.com/Morvex885/pulsar):
Яндекс Станция Миди / Лайт 2; [linux-voice-assistant](https://github.com/OHF-Voice/linux-voice-assistant))
**без Home Assistant**. Для колонки orbita выглядит как HA: подключается по ESPHome Native API и
ведёт голосовой диалог.

Входит в orbita: протокол голосового диалога, конец фразы (VAD), цепочка обработчиков (таймеры,
правила, LLM, MQTT), потоковая озвучка ответа, HTTP-раздача звука колонкам, объявления, MQTT.

Не входит в orbita (отдельные сервисы): распознавание речи, синтез речи, LLM. Для них в
репозитории есть серверы в `servers/` (§5.4). Активационное слово распознаёт колонка.

## 2. Термины

- **Колонка, спутник** — устройство с ESPHome API и голосовым ассистентом.
- **Ход** — одна реплика пользователя и ответ на неё; **диалог** — ходы с одним `conversation_id`.
- **Фраза ответа** — кусок ответа LLM, который синтезируется и отдаётся колонке отдельно (§4.4).
- **Задержка ответа** — от конца речи пользователя до первого звука ответа на колонке (NFR-1).

## 3. Архитектура

```
колонка ──ESPHome API (Noise)──► orbita ──► STT  POST /v1/audio/transcriptions
   ▲  звук 16 кГц, события            │ ──► LLM  POST /v1/chat/completions (stream)
   │                                  │ ──► TTS  POST /v1/audio/speech (wav)
   └──── HTTP GET :10800/tts/… ◄──────┘ ◄─► MQTT (необязательно: Node-RED, Zigbee2MQTT)
```

Модули: `satellite.py` (соединение и протокол), `vad.py`, `speech.py` + `openai_io.py` (STT/TTS/LLM
по OpenAI API), `streaming.py` + `sentences.py` (потоковый ответ), `intents.py` (обработчики,
история), `timers.py`, `bus.py` (MQTT), `http_store.py` (файлы и потоки), `audio.py` (PCM/WAV).

## 4. Функциональные требования

### 4.1 Колонки

- **FR-1.** orbita держит соединение с каждой колонкой из `satellites` по ESPHome Native API,
  с шифрованием Noise, если задан `noise_psk`, и сама переподключается при обрыве.
- **FR-2.** Колонки обслуживаются независимо и одновременно; имя колонки — в логах и топиках MQTT.
- **FR-3.** orbita передаёт колонке время и часовой пояс (`timezone`, пусто — пояс сервера).
- **FR-4.** У колонки можно переопределить язык распознавания (`language`), голос (`voice`) и
  потоковую озвучку (`streaming`).

### 4.2 Голосовой ход

- **FR-10.** На `VoiceAssistantRequest(start)` orbita принимает звук по самому API-соединению
  (порт 0) и проходит события как HA: `RUN_START`, `STT_START`, `STT_VAD_START`, `STT_VAD_END`,
  `STT_END{text}`, `INTENT_START`, `INTENT_END{conversation_id, continue_conversation}`,
  `TTS_START{text}`, `TTS_END{url}`, `RUN_END`.
- **FR-11.** Конец фразы определяет orbita (VAD: pymicro-vad, запасной — по энергии): после
  `vad.silence_seconds` тишины вслед за речью — `STT_VAD_END`; без речи `no_speech_seconds` —
  ход без текста; ход не дольше `timeout_seconds`.
- **FR-12.** Ошибки хода — `ERROR{code}` + `RUN_END`: `stt-no-text-recognized` (ничего не
  сказано), `stt-stream-failed` (распознавание недоступно), `tts-failed`, `pipeline-failed`.
- **FR-13.** Ответ, не идущий потоком, синтезируется целиком и отдаётся ссылкой на файл
  `http://<orbita>:10800/tts/<id>.<ext>`; файлы и потоки живут `http.ttl_seconds`.
- **FR-14.** Если ответ кончается вопросом и `continue_on_question`, колонка слушает дальше без
  активационного слова (`continue_conversation=1`); тот же `conversation_id` действует 30 с.
- **FR-15.** orbita пишет в журнал задержку хода: через сколько после конца речи готов текст
  и первый звук ответа (`heard … after it ended`, `answer audio ready …`).

### 4.3 Кто отвечает

- **FR-20.** Обработчики из `intents` спрашиваются по порядку; отвечает первый, вернувший
  ответ. Упавший обработчик пропускается. Никто не ответил — `fallback_reply`, а если при этом
  хоть один упал — `error_reply`.
- **FR-21. Таймеры** (`timers`) по-русски: поставить (числа словами и цифрами), отменить,
  «сколько осталось», уточнение «на сколько?». Отсчёт и звонок — на колонке.
- **FR-22. Правила** (`rules`): регулярное выражение → ответ с подстановками `{time}`, `{date}`,
  `{weekday}`, группами выражения; необязательно — сообщения MQTT.
- **FR-23. LLM** (`openai`): OpenAI-совместимый `/chat/completions`, история диалога
  `max_history` пар реплик, свой системный промпт `system`, параметры `temperature`,
  `max_tokens`, `top_p`, `extra_body` (например, `chat_template_kwargs: {enable_thinking: false}`).
- **FR-24.** Начало промпта LLM не меняется от хода к ходу: системное сообщение и история
  одинаковы, дата и время — в начале последнего сообщения пользователя
  (`[понедельник, 26 октября 2026, 21:45]\n…`); в истории — текст без них. Так сервер LLM берёт
  посчитанное из кэша (D-4).
- **FR-25.** Ответ LLM приводится к произносимому: без разметки и списков, в одну строку.
  Буквы не заменяются: латиница внутри русских слов — забота модели (NFR-8, D-9).
- **FR-26.** История диалога видит ответы всех обработчиков, не только LLM.
- **FR-27. MQTT-обработчик** (`mqtt`): вопрос в `orbita/<колонка>/intent`, ответ из
  `…/intent/reply` за `timeout`; пустой текст — «не моё», дальше по цепочке.

### 4.4 Потоковый ответ

- **FR-30.** При `tts.streaming` (по умолчанию) ответ LLM звучит по фразам, пока модель пишет:
  в `RUN_START{url}` колонка получает адрес потока `…/tts/stream/<id>.wav`; с первым звуком —
  `INTENT_PROGRESS{tts_start_streaming=1}`.
- **FR-31.** Текст режется на фразы по `.` `!` `?` `…` `;` перед словом с заглавной буквы и по
  переносам строк; фразы короче `tts.min_phrase_chars` склеиваются со следующей.
- **FR-32.** Фразы синтезируются по очереди и дописываются в один WAV с неизвестной длиной;
  каждый читатель получает поток с начала. Звук другого формата, чем у первой фразы,
  отбрасывается.
- **FR-33.** `TTS_END` несёт тот же адрес потока; `RUN_END` — когда озвучена последняя фраза.
  Если поток LLM оборвался после начала ответа, озвучивается полученная часть.
- **FR-34.** Ответы правил, таймеров и MQTT идут одним файлом.

### 4.5 Объявления и MQTT

- **FR-40.** `orbita/<колонка>/announce` (текст или `{"text", "media_url",
  "start_conversation"}`) — колонка произносит текст или играет ссылку; со
  `start_conversation` — слушает ответ.
- **FR-41.** С `mqtt.host` orbita публикует `status` (retained `online`/`offline`), `transcript`,
  `reply`, `timer` (см. README, «MQTT») и переподключается к брокеру с паузой до 60 с.

### 4.6 Внешние API

- **FR-50.** Распознавание, синтез и LLM — только через OpenAI-совместимые API (D-1); у `stt` и
  `tts` может быть своя секция `openai` (`base_url`, `api_key`), иначе общая.
- **FR-51.** Конфиг со старыми ключами Wyoming (`engine`, `host`, `port`, `speaker` в `stt`/`tts`)
  — ошибка с подсказкой, что указать вместо них.
- **FR-52.** Ключ API — из конфига или `OPENAI_API_KEY` (`/etc/orbita/env`).

## 5. Контракты внешних сервисов

### 5.1 Распознавание: `POST {stt.openai.base_url}/audio/transcriptions`

multipart: `file` — WAV 16 кГц 16 бит моно, одна фраза (до 60 с, обычно 2–15),
`model` = `stt.model`, `language` = язык колонки или `stt.language`, `response_format=json`.
Ответ `{"text": "..."}`; пустая запись — пустой текст, не ошибка.

### 5.2 Синтез: `POST {tts.openai.base_url}/audio/speech`

JSON `{model, input, voice, response_format, speed?}`. Для потокового ответа orbita всегда
просит `wav` (PCM); частота должна быть одна у всех фраз ответа (FR-32). Для файлов —
`tts.response_format` (`wav` надёжнее всего для GStreamer колонки).

### 5.3 LLM: `POST {openai.base_url}/chat/completions`

`stream: true` (SSE) для потокового ответа, иначе обычный ответ. Рассуждения модели
(`reasoning_content`) не озвучиваются; для скорости их стоит выключать (`extra_body`).

### 5.4 Серверы из `servers/`

Общее для всех: aiohttp, один файл, unit в `systemd/`, `GET /v1/models`, `GET /health`, ошибки
`{"error": {"message": ...}}`, ключ `--api-key` по желанию, модель загружается и прогревается
при старте, запросы выполняются по очереди.

- **gigaam_openai.py** (STT, :8001) — GigaAM (`v3_e2e_rnnt` по умолчанию, с пунктуацией),
  `response_format` json/text, только `ru`, до 25 с. На GPU: один поток для модели, звук
  дополняется нулями до кратного 2 с (модели передаётся настоящая длина — текст тот же),
  прогрев на речи (`--warmup`) и на всех длинах.
- **piper_openai.py** (TTS, :8002) — стоковый Piper, `wav`/`pcm`, `speed`.
- **wyoming_openai.py** (TTS, :8003) — мост к Wyoming-синтезатору (для движков, которые есть
  только как Wyoming-серверы). Отдаёт только голоса из `--voices` (первый — по умолчанию,
  остальные имена заменяются им): wyoming-piper числит установленным весь каталог и скачивает
  голос при первом обращении. `speed` не поддерживается. Прогрев: голос по умолчанию последним.

## 6. Нефункциональные требования

- **NFR-1. Задержка ответа** (от конца речи до первого звука, замер по звуку на колонке,
  `scripts/latency.py`). Цель: ответ правила ≤ 1,5 с, ответ LLM ≤ 2,0 с.
  Сейчас (27.10.2026, linux-voice-assistant, Qwen3.5-9B): правило 1,69–1,70 с, LLM 2,1–2,4 с;
  из них ожидание тишины 0,8 с, доставка звука от колонки ~0,6 с, распознавание 0,1 с, первая
  фраза LLM + синтез 0,7–0,9 с. Цель пока не достигнута (§9).
- **NFR-2.** Распознавание фразы 2–5 с — ≤ 0,2 с; синтез фразы — ≤ 0,5 с.
- **NFR-3. Ресурсы.** Самой orbita хватает 1 ядра и 256 МБ. Сервисы на общей видеокарте с LLM
  не должны выходить за её память: держать в памяти один голос синтеза.
- **NFR-4. Автозапуск.** После перезагрузки хоста все контейнеры и сервисы поднимаются сами,
  в порядке: модели (CT 100) → синтез на CPU (CT 102) → orbita (CT 101). Устройства NVIDIA
  создаются до запуска контейнеров. orbita переподключается к колонкам и сервисам сама.
- **NFR-5. Качество речи.** Ударения, омографы, «ё», числа, проценты, время и годы
  произносятся правильно (D-3, D-5).
- **NFR-6. Безопасность.** Колонки — по Noise с ключом; секреты — в `/etc/orbita/env` (0640);
  сервисы systemd с `ProtectSystem=strict` и без лишних прав.
- **NFR-8. Качество ответов LLM** (`scripts/llm_eval.py`, 32 голосовых вопроса; у фактов с
  числами проверяется и число). Цель: факты ≥ 95 %, ни одного ответа с латиницей в русских
  словах или буквами чужих алфавитов, ни одного «выполнила» на команду, которую LLM выполнить
  не может; первая фраза — медиана ≤ 0,5 с. Сейчас (Qwen3.5-9B Q4_K_M): факты 54/60 (90 %) —
  все ошибки в точных числах (высота Эльбруса, длина Волги), латиница и чужие буквы 0 из 96,
  на «включи свет» — «Я не могу управлять устройствами», первая фраза 0,44 с. Не достигнута
  только точность чисел (§9).
- **NFR-7. Лицензии.** Внешние модели и код подключаются как зависимости при установке, в
  репозиторий не кладутся. Silero (CC BY-NC-SA 4.0) — только некоммерческое использование;
  у mitrokun/espeak-ng-data файла лицензии нет.

## 9. Открытые вопросы

- NFR-1: сократить ожидание тишины (0,8 с → 0,5 с или адаптивно по длине фразы, как в HA) и
  отдавать в синтез первый кусок ответа по запятой; понять, откуда 0,6 с доставки звука у
  linux-voice-assistant; замерить задержку на колонке с pulsar.
- Тестовая колонка слушает виртуальный микрофон; вернуть USB-микрофон
  (`virtual-mic.conf` в CT 103).
- NFR-8: модель путает точные числа (высоты, длины). Варианты: другая модель в ≈6,2 ГиБ
  видеопамяти, справочные числа — правилами или инструментами, а не памятью модели.
- Распознавание синтезированных тестовых фраз голосом fr6800: «високосном» → «лисокосном»,
  «Какая длина у реки Волги» → «Кокодин о реке Волге»; на живом голосе проверить с USB-микрофоном.
  На неразборчивый вопрос Qwen однажды ответил отказом про «отсылку к самоубийству».
- TeraTTS — сравнить, когда будет видеопамять (D-6).
- Закрепить IP контейнеров (сейчас DHCP).
- llama.cpp не проверяет ключ API, хотя `LLAMA_ARG_API_KEY` задан.
- Проверить NFR-4 настоящей перезагрузкой pve3.

## 10. Решения

- **D-1. Только OpenAI-совместимые API** (26.10.2026). Wyoming убран из orbita: универсальнее,
  проверяется `curl`; потоковая отдача Wyoming не даёт выигрыша, потому что orbita и так
  синтезирует по фразам. Wyoming-движки подключаются мостом `wyoming_openai.py`.
- **D-2. GigaAM вместо faster-whisper** (26.10.2026): лучше для русского, меньше, быстрее
  (0,06–0,11 с против 0,19 с на фразу), освобождает видеопамять.
- **D-3. Русский Piper mitrokun на GPU** (26.10.2026): исправленный словарь espeak-ng,
  silero-stress, ёфикатор, нормализация; голоса из rraaww/ru_piper. Стоковый Piper (irina) —
  запасной, на CPU в CT 102.
- **D-4. Время — в последнем сообщении, не в системном** (26.10.2026): системный промпт
  неизменен, llama.cpp переиспользует кэш (42 токена вместо 279, ответ 0,43 с вместо 0,72 с).
- **D-5. Голоса** (26.10.2026): по умолчанию `ru_RU-fr6800-medium` (женский — фразы orbita
  в женском роде: «я не поняла»), мужской `ru_RU-dict-medium_epoch3874`. Отклонены на слух:
  irina (стоковая), mari (грустная), terra5871.
- **D-6. TeraTTS отложен** (26.10.2026): на видеокарте рядом с LLM, GigaAM и Piper свободно
  ~0,75 ГБ, а процессор хоста без AVX2.
- **D-7. Silero TTS не внедрён** (26.10.2026): процессор без AVX2, лицензия NC, в сообществе
  оценивают ниже доработанного Piper.
- **D-8. LLM — Qwen3.5-9B Q4_K_M вместо ornith-1.5-9B** (27.10.2026, выбрано в сессии
  local-llm по `scripts/llm_eval.py`): факты 90 % против 81–83 %, ни латиницы, ни иероглифов,
  не притворяется, что выполнила команду; занимает 5,5 ГБ видеопамяти вместо 5,9.
- **D-9. Без замены латиницы на кириллицу** (27.10.2026): замена появилась из-за ornith,
  с Qwen3.5 латиницы в русских словах нет (0 из 96); ошибки модели не маскируются.

## 11. Проверка

- Модульные и сквозные тесты: `pytest` (сквозные — против `api_selftest` из pulsar, иначе
  пропускаются); STT/TTS/LLM в тестах — поддельный OpenAI-сервер (`tests/fakes.py`).
- Голосом без колонки: `scripts/make_utterance.py` синтезирует «активационное слово +
  команда» (слово — английским голосом: `--wake-tts http://192.168.250.103:8002/v1`),
  `scripts/latency.py` проигрывает её в виртуальный микрофон linux-voice-assistant и меряет
  задержку по звуку (NFR-1).
- LLM: `scripts/llm_eval.py --base-url … --model …` — факты (с числами), чужие алфавиты, латиница,
  разметка, время до первой фразы (NFR-8); отчёты — в `docs/llm-eval/`.
- Серверы `servers/` проверяются запросами по их API: фраза, тишина, параллельные запросы,
  ошибки, `/v1/models`, `/health` (см. measurements.md).
